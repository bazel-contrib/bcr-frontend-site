README

TinyBVH

High-performance header-only BVH construction and traversal library, written in C++14 / "Sane C++" (or "C with classes"), with C++17 for threading. A C API is also provided. This library has no dependencies.

Current version: 1.9.2.

TinyBVH is fast. Here is, in a nutshell, how it compares to Intel's Embree and Madmann91's BVH library:

TinyBVH builds a SAH BVH faster than Embree and Madmann91, and traces individual primary and occlusion rays faster than those libraries. These results come from tiny_bvh_benchmark.cpp and are cautiously presented as 'preliminary'; single-ray traversal is only a small part of Embree. If you suspect an imperfection in the experiment setup, please let me know.

On the GPU, (multicore) CPU performance is dwarfed: TinyBVH traces up to 5 billion rays per second on a RTX5080 laptop GPU in Crytek's Sponza using the basic binary BVH format, regardless of graphics API and without relying on ray tracing hardware. That is 5 rays per pixel at 4k@120Hz.

Getting started

The library is tiny_bvh.h plus five headers next to it: tiny_bvh_base.h (platform-neutral code) and the SIMD kernels for x86 (tiny_bvh_x86_float.h, tiny_bvh_x86_double.h) and ARM (tiny_bvh_arm_float.h, tiny_bvh_arm_double.h). Keep them together, include only tiny_bvh.h, and define TINYBVH_IMPLEMENTATION in exactly one translation unit.

For a single header with only the parts you use, see the online customizer.

Basic use of the library:

#define TINYBVH_IMPLEMENTATION
#include "tiny_bvh.h"

tinybvh::BVH bvh;
bvh.Build( (tinybvh::bvhvec4*)myTriData, triangleCount );
tinybvh::Ray ray( tinybvh::bvhvec3( 0, 0, 0 ), tinybvh::bvhvec3( 0, 0, 1 ) );
bvh.Intersect( ray );   // hit if ray.hit.t < BVH_FAR; see ray.hit.prim, ray.hit.u, ray.hit.v

Here, myTriData holds three vertices per triangle, each four floats: x, y, z and a dummy value that exists purely for a more efficient memory layout. bvh.Intersect( ray ) finds the nearest intersection along the ray. Shadow rays use bvh.IsOccluded( ray ).

See tiny_bvh_minimal.cpp for a (really) small example, and the Basic Use and Advanced Topics manuals for more. New to BVHs? Start with this series of articles.

Builders

Build forwards to a specialized builder, selected via bvh.settings:

setting builder
(default) Bonsai (Ganestam et al., 2015): grid cells become mini trees, built in parallel with the SIMD binned SAH builder, then pruned and combined under a top tree.
useSpatialSplits Bonsai HQ (Ganestam & Doggett, 2016): adds SAH-guided triangle splitting.
binnedBVH Binned SAH with the AVX (x86) or NEON (ARM) builder; with useSpatialSplits: SBVH (Stich et al., 2009), including "unsplitting".
useSIMDifavailable = false Scalar reference binned SAH builder; SBVH with useSpatialSplits.
usePresplitting Pre-splits triangles before building (Karras & Aila, 2013; explanation by BoyBaykiller).
useFullSweep Full-sweep SAH builder, for experiments (with support from BoyBaykiller).
useHPLOC H-PLOC; builds trees identical to the NexusBVH CUDA code, for comparisons.

Additional settings can be found in struct BVHBuildSettings. All settings are per-BVH and are passed on to the layouts a BVH is built from:

tinybvh::BVH4_CPU bvh;
bvh.settings.useSpatialSplits = true;   // Bonsai HQ
bvh.Build( (tinybvh::bvhvec4*)myTriData, triangleCount );

For backwards compatibility with older versions of the library, BuildHQ builds with spatial splits for that one build, and BuildSIMD invokes the SIMD builder directly.

Layouts

TinyBVH offers a broad range of BVH layouts, specialized for various use cases.

layout description
BVH 32-byte nodes, two per cache line. Every other layout is produced from this one.
BVH_Verbose 64-byte nodes with child and parent indices, for tree surgery and the optimizer.
MBVH<M> M-wide intermediate format (Wald et al., 2008), used to produce the wide layouts.
BVH4_CPU AVX2 / NEON 4-wide traversal ("WiVe"), with octant-specialized kernels and four triangles per leaf. The fastest option on CPU.
BVH8_CPU AVX2 8-wide WiVe traversal, left in for reference.
BVH_GPU 64-byte nodes storing both child AABBs (Aila & Laine, 2009), for a simple GPU kernel.
BVH4_GPU Compact quantized 4-wide format for GPU ray tracing.
BVH8_CWBVH 80-byte compressed 8-wide nodes for state-of-the-art GPU traversal (Ylitie et al., 2017; code by AlanIWBFT). CWBVH_COMPRESSED_TRIS is off by default.
BVH4_AMD_HW AMD hardware BVH4 format (BOX32 and triangle nodes), RDNA3 and up. By Alessandro Salo.
CWBVH8_AMD_HW AMD RDNA4 hardware BVH8 format: BOX32 nodes, and primitive nodes holding up to eight triangle pairs. By Alessandro Salo.
BVH_DOBB Experimental. 8-wide compressed nodes whose child boxes are stored in one of 104 discrete rotated frames (Kern et al., 2025). By mmmuscus.
VoxelSet 256³ brick-based voxel object with DDA traversal, usable as a BLAS.
BVH_Double, BVH4_Double Double-precision BVH and BVH4_CPU (AVX2 and NEON kernels), with 64-bit indices.

Every layout is a template on scalar and index type: <float, uint32_t>, or <double, uint64_t> for the double precision ones. The wide CPU layouts fall back to portable scalar traversal where AVX2 or NEON is unavailable.

Geometry and traversal

bvh.Build( vertices, indices, triangleCount );          // indexed geometry
bvh.Build( bvhvec4slice( vertices, count, stride ) );   // interleaved vertex buffer (by David Peicho)
bvh.BuildAABB( aabbs, primCount );                      // BVH over AABBs
int32_t steps = bvh.Intersect( ray );                   // closest hit; result in ray.hit
bool occluded = bvh.IsOccluded( ray );                  // any hit, for shadow rays
bool hit = bvh.IntersectSphere( pos, r );               // sphere/BVH collision detection

Geometry passed to Build is referenced, not copied. The exception: BVH::Save embeds the triangles by default, so a BVH loaded from such a file owns its geometry (FreeGeometry releases it).

  • Hit record. t, barycentrics u and v, prim, and the instance index: a separate field, or the top bits of prim when INST_IDX_BITS is below 32. Plus 64 bytes of user data (a void* and a 56-byte union).
  • Ray masks. 16-bit masks on rays and BLASInstances; instances are skipped when they do not overlap, as in OptiX (by Romain Augier).
  • Bundles. IntersectBundle and IsOccludedBundle on BVH and BVH4_CPU trace TINYBVH_BUNDLE_RAYS rays at a time (WiVeC, AVX2).
  • Opacity micro maps. SetOpacityMicroMaps( mapData, N ) attaches an N×N opacity map per triangle (Gruen et al., 2020), applied in the SIMD leaf tests.
  • Triangle tests. Möller & Trumbore by default; Baldwin & Weber (2016) for the precomputed leaf formats; WATERTIGHT_TRITEST selects watertight intersection (Woop et al., 2013).

TLAS, instancing and custom geometry

A Top-Level Acceleration Structure is a BVH over instances, each referencing a BLAS with a 4x4 transform. BLASes of different layouts can be mixed, and a BLAS can be instanced many times:

tinybvh::BVH blas;
blas.Build( (tinybvh::bvhvec4*)myTriData, triangleCount );
tinybvh::BLASInstance inst[2];
inst[0].blasIdx = inst[1].blasIdx = 0;
inst[1].transform = myMatrix;   // instance transform; inverted by the TLAS build
tinybvh::BVHBase* blasList[] = { &blas };
tinybvh::BVH tlas;
tlas.Build( inst, 2, blasList, 1 );
tlas.Intersect( ray );

Changing transforms and rebuilding the (small) TLAS gives cheap rigid animation. Custom primitives work through callbacks: an AABB function, plus customIntersect and customIsOccluded. This also works for double-precision BVHs, so triangles, custom geometry and voxel objects can share one scene.

Maintaining a BVH

  • Refit. Refit updates bounds for moved triangles: much faster than a rebuild, and fine for subtle animation. It does not work when the triangle count changes, nor for trees with spatial splits; isRefittable() tells you which.
  • Optimize. Optimize( iterations, mu, epsilon ) lowers SAH cost by parallel reinsertion (Meister & Bittner, 2018), on the thread pool; mu sets the search density (higher is sparser and faster). Also available as settings.postOptimize. Changed in 1.9.2: the extreme and stochastic flags are gone. For static scenes, bvhopt goes much further.
  • Tree surgery. Compact (multi-threaded), MergeLeafs( maxLeafPrims ), SplitLeafs, CollectNodes and Depth.
  • Quality metrics. SAHCost, and EPOCost: "End-Point Overlap" (Aila et al., 2013), weighted by W_EPO.
  • Serialization. Save (returns false on failure) and Load for BVH, BVH4_CPU, BVH8_CPU, BVH4_GPU, BVH8_CWBVH, BVH4_AMD_HW and CWBVH8_AMD_HW. Every layout also has a static Load( fileName, context ) that returns a finished object, converting a plain-BVH file where needed.

Offline optimization: bvhopt

Where quality matters more than build time (static geometry, a tree you build once and ship), tools/bvhopt.cpp spends as long as it takes. It uses only the public API.

bvhopt <file.bvh> [options]                    optimize a binary BVH saved with its geometry
bvhopt <mesh.bin> --target <list> [options]    build optimized BVHs from a mesh

The first form writes <file>_opt.bvh. The second takes a mesh (a uint32 triangle count, then three float4 per triangle) and writes one BVH per target: bvh, bvhgpu, bvh4cpu, bvh8cpu, bvh4gpu, bvh8cwbvh, bvh4amdhw, cwbvh8amdhw, or all; each loads with its layout's static Load. It builds SBVH and spatial-split Bonsai candidates, optimizes them, collapses them with and without ray-visit weighting, and keeps the variant with the fewest box tests. Optimization rounds combine reinsertion, exact treelet restructuring, subtree rebuilds and reference unsplitting, followed by exact leaf formation for small subtrees.

-profile fast|hq|extreme sets how hard to look (a higher profile never returns a worse tree); -metric sah|epo|raycost sets what to minimize. -advanced lists the rest, such as a spatial-split prepass, geometry audit and repair, a measured round gate and fitting c_trav/c_int to timings.

Tools

Stand-alone utilities in tools/, each a single source file with build instructions at the top:

tool purpose
bvhopt.cpp Offline BVH optimizer, see above.
tinybvh_custom.cpp Generates a single header with only the layouts, features and ISAs you need, optionally without templates. Also available online.
bvhcrop.cpp Crops or decimates a .bin mesh, to reproduce build problems on a smaller scene.
obj2bin.cpp Converts .obj to .bin, with a colour estimated from the materials in w.
tinyfmt.cpp Applies the TinyBVH coding standard to the headers.

C API

tiny_bvh_c.h is a plain C99 interface (C11 preferred), implemented by tiny_bvh_c.cpp, which contains TinyBVH and builds as a static or shared library. Each BVH is an opaque handle created for one layout. Functions return a tbvh_result, fatal errors inside TinyBVH come back as error codes rather than ending the process (except on build worker threads), and rays, hits and instances are binary-compatible with the C++ types. Opacity micro maps are not exposed yet.

tbvh_bvh* bvh;
tbvh_create( TBVH_LAYOUT_BVH4_CPU, NULL, &bvh );
tbvh_geometry geo = { vertices, vertexCount, 0 /* stride: 16 */, NULL, 0 /* all triangles */ };
tbvh_build( bvh, &geo, TBVH_QUALITY_DEFAULT );
tbvh_ray ray;
tbvh_ray_init( &ray, 0, 0, 0, 0, 0, 1, 1e30f );
if (tbvh_intersect( bvh, &ray ) >= 0 && ray.hit.t < 1e30f) { /* ray.hit.prim, ray.hit.u, ray.hit.v */ }
tbvh_destroy( bvh );

Memory and threading

Each layout owns its buffers, so the classes are move-only; ReferenceFrom, ReleaseOwnership and DropReference share buffers explicitly. Allocation and build parallelism go through BVHContext: malloc, free, spawn, barrier and parallel_for hooks, plus userdata. By default they use a built-in std::thread pool, created on the first threaded build and released at exit or by tinybvh_shutdown_builtin_pool. Define TINYBVH_NO_BUILTIN_POOL to bring your own pool (thanks Wenzel Jakob), or NO_THREADED_BUILDS to drop threading; TinyBVH then compiles as C++14. settings.enableThreading = false keeps a build on the calling thread, for applications that build many BLASes at once, one per thread.

Fatal errors, including failed allocations, go through tinybvh_fatal_error, which never returns; install your own handler with tinybvh_set_fatal_error_handler.

Configuration

Define these before including tiny_bvh.h:

define effect
TINYBVH_IMPLEMENTATION emit the implementation in this translation unit
BVHBINS, HQBVHBINS bins for regular / SBVH construction (default 8; SBVH at most MAXHQBINS)
C_INT, C_TRAV default SAH cost of a primitive intersection / traversal step
W_EPO weight of 'end point overlap' in the EPO calculation
INST_IDX_BITS bits for the instance index; 32 stores it in a separate field
TINYBVH_STACK_SIZE CPU traversal stack size (default 128)
TINYBVH_BUNDLE_RAYS rays per IntersectBundle call; multiple of 8, max 256
WATERTIGHT_TRITEST watertight ray/triangle intersection
NORMALIZE_RAY_DIR normalize ray direction in the Ray constructor
DOBB_ALPHA BVH_DOBB: rotate a node if its oriented surface area is below alpha times its AABB area (default 0.9)
TINYBVH_USE_CUSTOM_VECTOR_TYPES 'Bring Your Own Vector Types' (thanks Tijmen Verhoef)
TINYBVH_ALIGNED_ALLOC / _FREE user-defined aligned allocation; define both (by Thierry Cantenot)
TINYBVH_NO_BUILTIN_POOL do not create the built-in thread pool
TINYBVH_NO_SIMD disable the SIMD paths
PARANOID extra bounds checks, for debugging
NO_DOUBLE_PRECISION_SUPPORT, NO_INDEXED_GEOMETRY, NO_CUSTOM_GEOMETRY, NO_THREADED_BUILDS, NO_VOXEL_SUPPORT compile out the corresponding feature

Threaded builds are tuned with the MT_* defines at the top of tiny_bvh.h.

Examples

A Visual Studio solution and a CMake file are included, but most examples are a single source file:

g++ examples/tiny_bvh_minimal.cpp
g++ -mwindows -O3 examples/tiny_bvh_viewer.cpp -I. -o tiny_bvh_viewer               # CPU ray tracing viewer
g++ -mwindows -O3 examples/tiny_bvh_pt.cpp -I. -o tiny_bvh_pt                       # multi-threaded path tracer
g++ -mavx2 -mfma -Ofast examples/tiny_bvh_speedtest.cpp -I. -o tiny_bvh_speedtest   # performance measurement

On macOS, use c++ --std=c++17 -framework Cocoa for the windowed examples and -framework OpenCL for the speedtest. The benchmark tool, which times and validates all builders and traversal kernels, builds with build.bat / build.sh.

The examples folder has many more small demos, among them OpenCL TLAS/BLAS traversal (tiny_bvh_gpu2.cpp), AMD hardware ray tracing with BVH4 and BVH8 (tiny_bvh_amd_hwrt.cpp, tiny_bvh_amd_hwrt_bvh8.cpp), a DOBB-BVH viewer (tiny_bvh_dobb_test.cpp), and OpenGL compute (tiny_bvh_gl_compute) and interop demos. The 'external' folder holds DXR and Vulkan benchmarks against TinyBVH; the Vulkan one also has OpenCL backends for the AMD hardware layouts.

GPU and platforms

GPU traversal examples are provided for OpenCL, OpenGL compute, DirectX12 and Vulkan. kernels/traverse_cwbvh.slang is a Slang port of CWBVH traversal (by Daniel Johansson), which compiles to SPIR-V, Metal, HLSL and the other Slang targets. For OpenCL, tiny_ocl.h is a single-header helper that selects a device, loads and compiles kernels (with include expansion, user defines and vendor/architecture #defines) and manages host/device buffers, including device-only ones. It links OpenCL.lib from the 'external' folder; tiny_bvh.h itself stays dependency-free.

TinyBVH builds with any C++17 compiler (C++14 without threading), including g++, clang, Visual Studio and Emscripten / WASM. Without AVX2 or NEON, every layout still builds and traverses on scalar code. Specifically supported:

  • x86-64 Windows/Linux: optimized SSE / AVX / AVX2 build and traversal kernels.
  • ARM NEON, including Android and Apple: NEON builder (by wuyakuma) and traversal kernels, aligned allocation on Android, and dedicated Apple paths.
  • AMD RDNA3 / RDNA4: BVH4_AMD_HW and CWBVH8_AMD_HW are traversed from OpenCL using AMD's BVH intersection intrinsics.

TinyBVH in the Wild

A list of projects using TinyBVH:

  • Remedy's Northlight engine uses TinyBVH in their editor and for baking per-micro-vertex displacements.
  • EA SEED's Gigi: uses TinyBVH for WebGPU ray tracing, "..as fast as when using the DXR api in DX12". Try the demo.
  • SideFX Houdini uses TinyBVH.
  • MuTracer by Yi Shen uses TinyBVH for real-time WebGPU path tracing in the browser.
  • wave_tracer by Shlomi Steinberg uses TinyBVH to trace path segments.
  • TrenchBroomBFG, by Robert Beckebans. "TinyBVH allows to load bigger glTF 2 maps almost instantly instead of minutes".
  • Jon Baker's Icarus Point Cloud visualizer uses TinyBVH to represent geometry.
  • The Wonderland Engine for web-based 3D uses TinyBVH for WebGL ray tracing.
  • unity-tinybvh: an example implementation of TinyBVH in Unity and a foundation for compute-based ray tracing, by Andrew MacIntyre.

Created or know about other projects? Let me know!
